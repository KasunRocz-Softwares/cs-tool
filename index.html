      // How it works

      From a log line on one server to an alert on your screen, in real time.

      1. 01

        Collect

        The agent samples CPU, memory, disk and network, and reads SSH, sudo and UFW logs for security events. If the backend is unreachable it buffers offline and retries.

      2. 02

        Ingest

        Batches arrive over HTTPS with a per-server API key. Keys are stored hashed, and each server gets its own.

      3. 03

        Store & alert

        TimescaleDB hypertables with continuous aggregates, retention and compression. The alert engine checks every sample as it lands.

      4. 04

        Watch live

        Metrics, security events, alerts and server status stream to the dashboard over WebSockets. No refreshing.

      // The dashboard

      Six workspaces. One console for ops, security, delivery and cost.

      // The agent

      Small enough to forget it's there.

      A Node.js agent packaged as a .deb with a systemd service. It runs as an unprivileged user with CPU and memory caps and filesystem hardening.

      // Alerting

      Alerts that raise themselves, and clear themselves.

      Every ingested sample is checked. Open alerts are de-duplicated per server and type, broadcast live, and auto-resolve when things recover. Thresholds are set with ALERT_* environment variables.

      • ThresholdCPUSustained load over your limit
      • ThresholdMemoryPressure before the OOM killer
      • ThresholdDiskVolumes filling up
      • SecuritySSH brute forceBursts of failed logins
      • AvailabilityServer offlineAgent stops reporting

      // Get started

      Running in one command.

      git clone https://github.com/KasunRocz-Softwares/cs-tool.git
cd cs-tool
cp backend/.env.example backend/.env   # optional
docker compose up --build
      • Dashboardhttp://localhost:5173
      • APIhttp://localhost:4000/api/v1
      • Databaselocalhost:5432

      The backend applies the database schema and seeds an admin user on first start.

      # Database
docker run -d --name tsdb -p 5432:5432 \
  -e POSTGRES_USER=monitor -e POSTGRES_PASSWORD=monitor -e POSTGRES_DB=monitoring \
  timescale/timescaledb:2.17.2-pg16

# Backend  (:4000)
cd backend && npm install && cp .env.example .env
npm run migrate && npm run start:dev

# Dashboard  (:5173)
cd dashboard && npm install && npm run dev
      1. In the dashboard, click + Add server and copy the one-time API key.
      2. On the Ubuntu server, build and install the package.
      3. Set server_url and api_key in /etc/monitor-agent/agent.yaml.
      4. Start the service and follow its logs.
      cd packaging && ./build-deb.sh
sudo dpkg -i ../dist/monitor-agent_1.0.0_all.deb
sudo systemctl enable --now monitor-agent
journalctl -u monitor-agent -f

      Before a real deployment: change JWT_SECRET, the database credentials and the seeded admin password, and set tls_verify: true on every agent.
