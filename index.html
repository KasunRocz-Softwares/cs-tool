      // How it works

      From a log line on one server to an alert on your screen, in real time.

      1. 01

        Collect

        The agent samples CPU, memory, disk and network, and reads SSH, sudo and UFW logs for security events. If the backend is unreachable it buffers offline and retries.

      2. 02

        Ingest

        Batches arrive over HTTPS with a per-server API key. Keys are stored hashed, and each server gets its own.

      3. 03

        Store & alert

        TimescaleDB hypertables with continuous aggregates, retention and compression. The alert engine checks every sample as it lands.

      4. 04

        Watch live

        Metrics, security events, alerts and server status stream to the dashboard over WebSockets. No refreshing.

      // The dashboard

      Six workspaces. One console for ops, security, delivery and cost.

      // The agent

      Small enough to forget it's there.

      A Node.js agent packaged as a .deb with a systemd service. It runs as an unprivileged user with CPU and memory caps and filesystem hardening.

      // Alerting

      Alerts that raise themselves, and clear themselves.

      Every ingested sample is checked. Open alerts are de-duplicated per server and type, broadcast live, and auto-resolve when things recover. Thresholds are set with ALERT_* environment variables.

      • ThresholdCPUSustained load over your limit
      • ThresholdMemoryPressure before the OOM killer
      • ThresholdDiskVolumes filling up
      • SecuritySSH brute forceBursts of failed logins
      • AvailabilityServer offlineAgent stops reporting

      // Get started

      Running on your server in five minutes.

      CS Tool ships as two Docker images. One compose file starts them with TimescaleDB and a proxy that serves the dashboard, the API and agent traffic from a single address.

      1. On any machine with Docker and Docker Compose v2.23+, download the two files.
      mkdir cs-tool && cd cs-tool
curl -fsSLO https://qulaxy.com/cs-tool/setup/docker-compose.yml
curl -fsSL -o .env https://qulaxy.com/cs-tool/setup/env.example
      1. Fill in the four required values in .env. On Linux this generates the secrets, then set your own ADMIN_PASSWORD:
      sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 16)|" .env
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -hex 32)|" .env
sed -i "s|^TOKEN_ENC_KEY=.*|TOKEN_ENC_KEY=$(openssl rand -hex 32)|" .env
nano .env   # set ADMIN_PASSWORD
      1. Start it, then open the dashboard and sign in with ADMIN_EMAIL and ADMIN_PASSWORD. The first sign-in asks you to set up two-factor with an authenticator app.
      docker compose up -d
      • Dashboardhttp://localhost:8080
      • API & agentshttp://localhost:8080/api/v1
      • Your domainSITE_ADDRESS=monitor.example.com

      For a domain with automatic HTTPS, set SITE_ADDRESS, PUBLIC_URL and WEBAUTHN_RP_ID to it and use ports 80 and 443. Update later with docker compose pull && docker compose up -d.

      1. In the dashboard, click + Add server and copy the one-time API key.
      2. On the Ubuntu server you want to monitor, download and install the agent package. It needs Node.js 18 or newer: Ubuntu 24.04 includes it, while older releases need a newer Node.js first (for example from NodeSource).
      curl -fsSLO https://github.com/KasunRocz-Softwares/cs-tool/releases/latest/download/monitor-agent_latest_all.deb
sudo apt-get install -y ./monitor-agent_latest_all.deb
      1. In /etc/monitor-agent/agent.yaml, set server_url to your CS Tool address (your PUBLIC_URL) and api_key to the key, then restart the agent and follow its logs.
      sudo nano /etc/monitor-agent/agent.yaml
sudo systemctl restart monitor-agent
journalctl -u monitor-agent -f

      To update an agent, run the same two install commands again; your agent.yaml is kept. Every package is on the releases page with SHA-256 checksums.

      # Build and run everything from the source
git clone https://github.com/KasunRocz-Softwares/cs-tool.git
cd cs-tool
docker compose up --build

# Or run the parts for development
docker run -d --name tsdb -p 5432:5432 \
  -e POSTGRES_USER=monitor -e POSTGRES_PASSWORD=monitor -e POSTGRES_DB=monitoring \
  timescale/timescaledb:2.17.2-pg16
cd backend && npm install && cp .env.example .env
npm run migrate && npm run start:dev        # :4000
cd dashboard && npm install && npm run dev  # :5173

# Build the agent package yourself
cd packaging && ./build-deb.sh   # -> dist/monitor-agent_<version>_all.deb

      Keep .env private. The admin password is reset to ADMIN_PASSWORD every time the API starts, so change it there. Set tls_verify: true on every agent once you use HTTPS.
